# Traffic forecasting experiment

Reproducible code for a one-step urban traffic-speed forecasting experiment.
The repository contains the implementation, input data, experiment notebook,
tests, pinned Python environment, protocol description, and the final
machine-readable results from the recorded run.

The public repository intentionally excludes thesis source files, bibliographies,
LaTeX documents, thesis-only diagrams, and local thesis-editing helpers. Those
files remain local to the author and are covered by `.gitignore`.

## Experiment

The canonical implementation is [`traffic_experiment.py`](traffic_experiment.py).
The executable notebook is [`experiment.ipynb`](experiment.ipynb).

The comparison uses:

- target: `traffic_speed` from `METR_LA_with_Weather_5min.csv`;
- 24 historical observations and a one-step forecast horizon;
- a chronological 70% / 10% / 20% train, validation, and test split;
- a `MinMaxScaler` fitted on training rows only;
- seed `42`, chronological data loaders, and batch size `64` for supervised models;
- validation-MAE early stopping with patience `5` and at most `20` epochs;
- zero-shot TimesFM 2.5 alongside supervised DSS-softmax and LSTM baselines.

The exact contract and dataset-window accounting are documented in
[`EXPERIMENT_PROTOCOL.md`](EXPERIMENT_PROTOCOL.md).

## Environment

Create an isolated Python 3.12 environment and install the pinned packages:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m ipykernel install --user --name bachelorthesis --display-name "Python (bachelorthesis)"
```

For a fully resolved environment, use [`requirements-lock.txt`](requirements-lock.txt).
The TimesFM checkpoint is downloaded on the first run that enables TimesFM.
The code uses CUDA when available and otherwise runs on the CPU.

## Running the experiment

Run a quick smoke test without downloading TimesFM. The smoke-test directory is
ignored by Git:

```powershell
.\.venv\Scripts\python.exe traffic_experiment.py --fast --output-dir outputs_smoke
```

Run the full three-model comparison:

```powershell
.\.venv\Scripts\python.exe traffic_experiment.py --run-timesfm --output-dir outputs
```

The full run trains the two supervised models, evaluates all 6,048 test
windows, and measures accuracy, parameter counts, training time, inference
latency, and peak process memory. On CPU it can take several minutes; the
initial TimesFM checkpoint download can take longer.

## Recorded results

The committed `outputs/` records are generated by the experiment code and are
not hand-edited:

- `outputs/metrics.csv` — MAE, RMSE, MAPE, task metadata, and sample counts;
- `outputs/efficiency.csv` — timing, parameter, device, and memory records;
- `outputs/run_metadata.json` — seed, split boundaries, scaler range, versions,
  hardware, and model metadata;
- `outputs/figures/metrics_by_unit.png` — accuracy overview;
- `outputs/figures/mae_rmse_speed.png` — MAE/RMSE in original speed units;
- `outputs/figures/mape_percent.png` — MAPE on a separate percentage axis;
- `outputs/figures/forecast_comparison.png` — aligned one-step predictions.

MAE and RMSE are reported in the original traffic-speed units; MAPE is reported
as a percentage. The results describe the recorded CPU run and should not be
interpreted as a universal ranking of model families.

## Tests and code checks

Run the regression tests:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Check that the Python sources compile:

```powershell
.\.venv\Scripts\python.exe -m py_compile traffic_experiment.py
```

The data directory contains the derived METR-LA five-minute table used by the
experiment and the retained source weather table. Weather columns are present
for provenance but are not model inputs in the primary comparison.
